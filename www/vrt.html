What is in a VRT?

A VRT is a small document that describes a dataset made of other datasets. There are four kinds: classic rasters (mosaics, band stacks, subsets, rescaling, pixel functions, warps), vrt:// strings, multidimensional arrays, and vector layers. Give this page one, by URL, as a vrt:// string, or pasted, and it says what kind it is, what every element does, which sources it names and how, and for a classic raster what a read would touch: the source windows, where they land, the operations on the way, and the source tiles under them.

The model and planner are vrt-model in WebAssembly, the same code that matches GDAL byte for byte on the VRT corpus. They read nothing. This page reads the document, any nested VRTs, and source headers when you ask (one or two range requests each). No pixels are read.

What a read touches

A read asks for a window of the VRT into a buffer of some size. The planner works out, for each source, the window of the source it needs, the whole pixels it asks for, and where they land in the buffer, through any nesting. It follows the reference library's window arithmetic and nearest-neighbour sampling exactly.

Each coloured box is one read landing in the buffer. Where boxes overlap, the later source wins, as in the reference library. Read the source headers to see which tiles or strips of each source a read needs (in the source grid beside the layout).

Tiles shown are at full resolution. For a reduced read the reference library may use a source overview instead, a choice the document does not state.
